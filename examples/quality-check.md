# Scenario 2: CSV Import and Quality Check

## 背景

数据质量是数据管道的生命线。在将数据导入系统之前，必须进行严格的质量检查，防止"垃圾进，垃圾出"。

本场景模拟一个数据工程师在导入新数据时发现质量问题，需要通过 Agent 识别问题、评估严重程度、并提出修复方案。

## 场景描述

你收到一份新的订单数据文件 `orders_quality_issues.csv`，需要在导入数据库之前进行质量检查。该文件包含多种常见的数据质量问题。

### 质量问题清单

| 行号 | 字段 | 问题类型 | 严重程度 | 描述 |
|------|------|---------|---------|------|
| 2 | `customer_name` | 空值 | warning | 客户姓名为空 |
| 3 | `quantity` | 负值 | critical | 数量为 -5，不应为负数 |
| 4 | `price` | 类型错误 | critical | 值为 "not_a_number"，无法转为数值 |
| 6 | `status` | 未知枚举值 | warning | 状态为 "unknown_status"，不在合法集合中 |
| 7 | `order_date` | 空值 | warning | 订单日期为空 |

## 执行步骤

### Step 1: 解析数据文件

```
解析 data/orders_quality_issues.csv 文件
```

**预期行为：**
- Agent 调用 `parse_data` 工具
- 返回文件基本信息：10 行、7 列
- 返回字段列表和数据样例

**预期输出：**
```
文件: data/orders_quality_issues.csv
格式: CSV
行数: 10
字段: order_id, customer_name, product, quantity, price, order_date, status
```

### Step 2: 执行质量检查

```
对这份数据执行质量检查，找出所有问题
```

**预期行为：**
- Agent 调用 `validate_quality` 工具
- 返回检查结果：4 个违规
- 每个违规包含：行号、字段、问题类型、严重程度

**预期输出：**
```
总行数: 10
违规数: 4
检查结果: 未通过

违规详情:
1. 行2, customer_name: 空值 (warning)
2. 行3, quantity: 负值 -5 (critical)
3. 行4, price: 类型错误 "not_a_number" (critical)
4. 行7, order_date: 空值 (warning)
```

### Step 3: 分析问题严重程度

```
按严重程度分类分析这些问题
```

**预期行为：**
- Agent 分析每个问题的影响
- 区分 critical（必须修复）和 warning（建议修复）
- 评估对下游系统的影响

**预期分析：**
```
Critical 问题 (2个):
1. quantity 负值: 导致库存计算错误、财务报表异常
2. price 类型错误: 导致金额计算失败

Warning 问题 (2个):
1. customer_name 空值: 影响客户分析，但不影响核心业务
2. order_date 空值: 影响时间序列分析，但不影响订单处理
```

### Step 4: 生成告警

```
对 critical 级别问题生成告警
```

**预期行为：**
- Agent 调用 `send_alert` 工具
- 使用 "error" 或 "critical" 级别
- 输出到控制台或日志文件

**预期输出：**
```
[CRITICAL] [2026-09-05T14:00:00Z] 数据质量问题: order_id=3003, quantity=-5 (负值)
[CRITICAL] [2026-09-05T14:00:00Z] 数据质量问题: order_id=3004, price="not_a_number" (类型错误)
```

### Step 5: 提出修复建议

```
对每个问题提出具体的修复建议
```

**预期行为：**
- Agent 为每个问题提供修复方案
- 区分自动修复和人工修复
- 估计修复成本

**预期建议：**
```
修复建议:

1. quantity 负值 (行3):
   - 方案A: 标记为退货记录，增加 order_type 字段
   - 方案B: 取绝对值，假设为录入错误
   - 自动修复: 可自动执行

2. price 类型错误 (行4):
   - 方案: 移除非数字字符，尝试解析
   - 自动修复: 可自动执行

3. customer_name 空值 (行2):
   - 方案: 填充默认值 "未知客户"
   - 自动修复: 可自动执行

4. order_date 空值 (行7):
   - 方案: 使用当前日期填充，或标记为 "未知"
   - 自动修复: 可自动执行
```

### Step 6: 执行自动修复（可选）

```
自动修复可以修复的问题
```

**预期行为：**
- Agent 调用 `transform_data` 工具
- 对 price 字段执行清洗（移除非数字字符）
- 对 quantity 字段取绝对值
- 对空值字段填充默认值

### Step 7: 输出质量评估总结

```
输出最终的质量评估报告
```

**预期行为：**
- Agent 生成结构化报告
- 包含问题统计、修复状态、建议措施
- 评估数据是否可以安全导入

**预期输出：**
```
数据质量评估总结

文件: data/orders_quality_issues.csv
检查时间: 2026-09-05T14:00:00Z

问题统计:
- 总行数: 10
- 问题行数: 4 (40%)
- Critical: 2
- Warning: 2

修复状态:
- 已自动修复: 2 (price 类型错误, quantity 负值)
- 需人工确认: 1 (customer_name 空值)
- 建议忽略: 1 (order_date 空值)

导入建议:
- 当前数据: 不建议直接导入
- 修复后: 可以导入，但需监控 customer_name 缺失的记录
```

## 演示要点

1. **多维度质量检查** — Agent 能检查空值、类型错误、范围异常、枚举值合法性
2. **严重程度分类** — Agent 能区分 critical 和 warning 级别问题
3. **告警生成能力** — Agent 能对关键问题生成即时告警
4. **修复建议能力** — Agent 能为每个问题提供具体的修复方案
5. **自动修复能力** — Agent 能调用工具执行可自动修复的问题
6. **报告生成能力** — Agent 能生成结构化的质量评估报告
